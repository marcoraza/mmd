Infra · iOS · Offline-first real

Galpão sem sinal vira não-problema

Hoje o app iOS é online-only: APIClient.swift faz request direto, sem fila. Se o galpão tem zona morta de Wi-Fi (e quase todo galpão tem), o scan trava. PowerSync + supabase-swift entrega sync local-first: o app escreve no SQLite, sobe quando voltar a rede. Conflict resolution incluso.

Apache 2.0 · MIT Swift · SQLite PowerSync sync engine github.com/powersync-ja ↗
O cenário real

Galpão tem ferro, concreto e zona morta — Wi-Fi cai

  • Marcelo escaneia 50 seriais com RFD40 em pilha de equipamento, perde sinal — operação para
  • Funcionário no evento (no porão de um casamento) tenta fazer check-in, request falha, ninguém sabe
  • App não tem cache local de catálogo — sem internet, não dá nem pra ver o que tem no estoque
  • Cada movimento perdido = inventário fora de sincronia = erro operacional no dia seguinte
O que ganhamos

App que funciona melhor offline do que online

  • SQLite local: catálogo inteiro espelhado no iPhone — abre instantâneo, busca instantânea
  • Fila de sync: toda movimentação fica em fila local até subir — zero perda de dados
  • Conflict resolution: dois funcionários movimentam o mesmo serial offline → PowerSync resolve por timestamp+regra
  • Realtime ao voltar online: mudanças do servidor aparecem no app sem F5
  • Caso de uso premium: Marcelo termina evento no domingo de noite, sync acontece no carro voltando pra casa, segunda já tem dashboard atualizado

Considerações

O que pesa nessa decisão

  • PowerSync free tier é generoso, mas escala vira pago em produção séria — modelar custo antes
  • Alternativa: SwiftData puro + sync manual — controle total, mais código nosso
  • Refactor do APIClient.swift é grande — toda chamada vira repository pattern com fonte local
  • RLS Supabase precisa permitir leituras paginadas em massa pro espelho local — modelar policies
Veredito

Não é prioridade 1, mas é diferencial competitivo de longo prazo.
