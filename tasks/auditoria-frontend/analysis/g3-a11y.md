# G3: Acessibilidade - WCAG 2.2 AA

## Estado Geral

O projeto tem base de acessibilidade acima da media para um MVP: usa aria-* em navegacao, botoes com aria-label, e focus-visible global. Porem, dialogs personalizados tem falhas criticas de focus management.

## Focus Management

### Focus Ring Global (Verifiquei)

`globals.css` linha ~185:
```css
:focus-visible {
  outline: 2px solid var(--accent-cyan);
  outline-offset: 2px;
  border-radius: var(--r-sm);
}
```
Correto: usa `focus-visible` (keyboard-only), contraste do cyan precisa validacao.

### Focus Trap em Dialogs (Alta Severidade - AUSENTE)

Verifiquei em todos os dialogs do projeto:
- `ConflictModal.tsx` linha 56: apenas `useEffect` para Escape, sem focus trap
- `CheckinDialog.tsx` linha 50: apenas `useEffect` para Escape, sem focus trap
- `CheckoutDialog.tsx` linha 26: apenas `useEffect` para Escape, sem focus trap
- `ItemSidePanel.tsx` linha 28: apenas `useEffect` para Escape, sem focus trap
- `UnitDrawer.tsx` linha 44: overlay mas sem verificacao de focus trap

Impacto: usuario de teclado pode "escapar" do modal e navegar pelo conteudo de fundo. Violacao WCAG 2.1.2 (No Keyboard Trap) na direcao oposta - e preciso trapping, nao fuga.

### Skip Links (Alta Severidade - AUSENTE)

`layout.tsx` define `id="main-content"` no `<main>`, mas nao ha:
```html
<a href="#main-content" class="sr-only focus:not-sr-only">Ir para conteudo principal</a>
```
Violacao WCAG 2.4.1 (Bypass Blocks).

### Focus Not Obscured (2.4.11)

O `SideRail` tem `zIndex: 2` e fica fixo na lateral. Potencial para obscurecer o focus ring de elementos proximos. Nao e possivel confirmar sem teste visual, marcado como Hipotese.

## ARIA Patterns

Verifiquei varios patterns:

Corretos:
- `role="dialog"` + `aria-modal="true"` + `aria-label`: ConflictModal, CheckinDialog, CheckoutDialog, ItemSidePanel
- `role="tablist"` + `aria-label` + `role="tab"` + `aria-selected`: CategoryNav, QrCodesClient, ProjectDetailClient
- `role="radiogroup"` + `role="radio"` + `aria-checked`: EditableStars, ConfigClient, CheckinDialog, CheckoutDialog
- `aria-current="page"` em SideRail: correto

Problemas:
- Dialogs personalizados (`role="dialog"`) sem `aria-describedby` para descricao adicional
- `role="button"` em div (`catalog/UnitsTable.tsx:211`) sem `tabIndex` associado verificado - possivel omissao de keyboard access

## Contraste WCAG 2.2 AA

Hipotese (nao e possivel calcular contraste sem renderizacao): 

Preocupacoes potenciais:
- `--fg-2: oklch(0.50 0.01 250)` no modo claro contra `--bg-0: oklch(0.97 0.005 250)` - L de 0.50 vs 0.97, contraste estimado abaixo de 4.5:1 para texto normal
- `--fg-3: oklch(0.65 0.01 250)` - ainda mais baixo, usado em labels secundarios
- Labels com `color: 'var(--fg-2)'` e `fontSize: 12` sao texto normal pequeno, exigem 4.5:1

Inferencia: fg-2 e fg-3 provavelmente nao passam no ratio 4.5:1 para texto normal. Sao usados extensivamente em labels, sublabels, mono text.

## Target Size (WCAG 2.5.8 - minimo 24x24px)

Verifiquei tamanhos de botoes:
- SideRail nav items: `width: 44, height: 44` - passa
- ThemeToggle: `width: 40, height: 40` - passa
- Botao fechar dialogs: `width: 28, height: 28` - passa (acima de 24)
- Estrelas em `EditableStars.tsx` - usa `size` prop, default nao verificado mas provavelmente >= 24

Risco: botoes "fechar" com 28px estao no limite. Espacamento ao redor pode reduzir area de click efetiva.

## Motion

Verifiquei `globals.css` linha ~220:
```css
@media (prefers-reduced-motion: reduce) {
  .reveal, .orbit-slow, .orbit-reverse, .pulse-soft, .skeleton {
    animation: none !important;
  }
  .reveal { opacity: 1; transform: none; }
}
```
Correto: animacoes CSS respeitam `prefers-reduced-motion`. Porem, apenas as classes CSS definidas no globals sao cobertas. Animacoes inline via `style={{ animation: ... }}` nos componentes podem nao ser cobertas.
