Infra · Já em uso · Garantir versão

O SDK oficial Zebra agora no GitHub em XCFramework

Já usamos o Zebra SDK no ZebraRFIDManager.swift. A novidade: a Zebra publicou no GitHub a versão XCFramework — mais nova que a CocoaPods antiga, com suporte oficial pro RFD40, RFD8500 e RF90. Mudança barata que evita surpresa quando o Marcelo comprar um reader novo.

SDK oficial Swift · ObjC XCFramework github.com/ZebraDevs/alt-rfid-ios-sdk ↗
Risco que ninguém vê

Estamos numa versão que pode estar desatualizada

  • O ZebraRFIDManager.swift importa ZebraRfidSdkFramework — não sabemos qual versão
  • Zebra historicamente entrega o SDK via portal corporativo + CocoaPods — versão pode ter ficado pra trás
  • Modelos novos de reader (RF90) podem não funcionar com a versão atual
  • Se a Apple atualizar o External Accessory framework, pode quebrar e a gente nem vê chegando
O que ganhamos

Atualização incremental do SDK + roadmap de hardware aberto

  • Versão XCFramework atual no GitHub — fácil rastrear releases, ver changelog
  • Compatibilidade oficial com RFD40 (que o Marcelo já tem), RFD8500 (alternativa) e RF90 (modelo novo, mais leve)
  • Issues e discussões públicas — quando der bug, não dependemos só do suporte Zebra
  • Documentação centralizada — atualizar README/onboarding do dev fica mais simples

O que olhar antes de subir versão

  • Confirmar que API delegate (srfidISdkApiDelegate) não mudou — nosso código depende disso
  • Testar com leitor real do Marcelo antes de deploy — não dá pra testar tudo no simulador
  • Licença do SDK ainda é proprietária Zebra — só o XCFramework é distribuído no GitHub
Veredito

Migra ainda esta sprint. 2h de manutenção, evita surpresa.

Não é feature, é higiene. Atualizar a referência do SDK no Xcode é simples, deixa o app preparado pra modelos novos de leitor, e desbloqueia features futuras (RFD40 tem modo "geiger" pra encontrar equipamento — quando a gente quiser implementar, vai precisar do SDK atual).
